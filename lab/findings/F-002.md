# F-002 — Asynchronous sampling turns a real change into a divergence

**Classification:** INTERPRETATION_GAP (semantic verification 2026-10-07): ORACLE §11 compares "posterior distributions" by a 7 % difference without defining the metric or the time alignment of classes sampled at different times; the result depends on the lab's H-FC-3/H-FC-4.  Open question Q-004 (architecture definition).
**Found by:** module `failure_chain` (S-LAB-02).  **Regression:** example `value_drop`; `tests/lab/test_findings.py`.

## Minimal reproduction

```
python -m lab run lab/findings/F-002.request.json --out f002.zip
```

The true value falls from 100 to 80 at step 6 (hourly steps).  Ground and autonomous
classes read every hour; the orbital class every 4 h or every hour.

| Variant | Divergence | Suspended steps | Evaluations | Final mode |
|---|---|---:|---:|---|
| `orbital_every_4h` | steps 6–7, spread 20 % (> 7 %) | 4 | 2 | INACTIVE (re-evaluated at step 10) |
| `orbital_every_1h` | none | 0 | 1 | ACTIVE on the old evaluation (F-001) |

With the slow class, the latest admissible orbital value (100, measured at step 4, within
its TTL) is compared with the new ground/autonomous values (80).  The comparison reports a
divergence, ORACLE §11 freezes state-based transactions, ETRANS §4.1 suspends dependent
outputs, and the re-entry recomputation happens to pick up the new state.  The re-evaluation
is caused by a sampling artefact, not by a rule — and with a faster orbital class it does
not happen at all (F-001).

## Chain of provisions

1. ORACLE §4.8 — "A statistically significant disagreement between posterior distributions
   produced by **independent oracle classes**."
2. ORACLE §11 (ORACLE-11-01) — "posterior distributions across independent oracle classes
   differ by more than **7%**."  Neither the metric nor the alignment in time is defined.
3. ORACLE §9 — data within TTL are admissible regardless of their age inside the TTL.
4. Lab hypothesis H-FC-3 — the latest admissible values are compared, without time alignment.

## Options for the author

| Option | Effect |
|---|---|
| A. Compare classes only on data measured within a common window | no false divergence from sampling; needs the window per data type |
| B. Define the divergence test on posteriors whose uncertainty grows with data age | an old value disagrees less "significantly"; needs an uncertainty model (ORACLE §10) |
| C. Keep the literal rule | changes are reported as divergences for up to one sampling interval of the slowest class; transactions freeze meanwhile |
