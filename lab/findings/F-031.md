## Analysis

**Pair 1 — how a territory joins.**

| | Code A.5 | INTEGRATION §4.1 |
|---|---|---|
| Subject | a new territory | an integrating entity |
| Object | connection | consent mechanism |
| Scope | after the startup cluster is online | every integration |
| Conditions | 67 % of the adult population and a Peace Stake | explicit, auditable consent |
| Modality | necessary condition ("only via") | permission ("MAY include") |

Joint compliance is possible.  A 67 % referendum with a Peace Stake satisfies both.  Refusing a
territory that offers only a legislative act also satisfies both, because INTEGRATION permits that
mechanism but does not oblige anyone to accept it.  The difference lies in the authority granted, not in
incompatible requirements (as in F-012).

**Pair 2 — sanctions before full integration.**

| | Code §7.3 / §8.1 / §8.2 | INTEGRATION §5.2 |
|---|---|---|
| Subject | an aggressor state ("the violating region") | a territory in Phase 1 |
| Modality | automatic slashing, disconnection, write-off | no sanctions or kill switches |

Joint compliance is possible if a Phase 0–1 territory is not yet "connected", so that the Code's rules
do not reach it.  It is impossible if it is connected.  No text maps "connect" to an INTEGRATION phase.
§5.3 lets Peace Staking activate only from Phase 2, while A.5 requires the stake at connection.

**Priority.** INTEGRATION §2 places it downstream of ORACLE, AXIOMS and SCOPE.  No rule ranks the Code
against INTEGRATION.
