# F-014 — No Calibration Bundle exists; by SIMULATION §4 every protocol that needs one is non-enforceable

**Classification:** CONFIRMED_FINDING (semantic verification 2026-10-07) — systemic blocker, decomposed in `lab/registry/calibration_map.json` / `lab/CALIBRATION_MAP.md` (open questions Q-034, Q-035).  The lab does not invent Calibration Bundles.
**Found by:** reading for S-LAB-05 and the open parameters of the other modules.
**Regression:** `tests/lab/test_findings.py` (quotes checked in the pinned corpus).

## Texts

- SIMULATION §2: any protocol or change that introduces "thresholds, activation conditions, composite
  indices, enforcement logic, calibration parameters, cross-layer dependencies" MUST pass
  DKP-8-SIMULATION-001 prior to activation; "No exception paths are permitted."
- SIMULATION §4: "Protocols lacking an attached and valid L8 Calibration Bundle are NON-ENFORCEABLE
  by definition."
- SIMULATION §10: "Expired calibration bundles automatically invalidate enforcement."
- HABITAT §6, ORACLE §12 (B(t)), IDENTITY §4.1 (attribution threshold), EXIT §6 (cooling period),
  CRISIS §6 (all crisis numbers) defer their parameters to SIMULATION.

The corpus contains no Calibration Bundle.  Read literally, every protocol with thresholds or
enforcement logic is non-enforceable today.  This is consistent with the lab's
`operational_use: false`, but it leaves open:

1. whether constants written into protocols — ORACLE §16 (4 %, 7 %, 14 days, 60 %, 80 %), ORACLE
   §17 TTLs, ERROR §7 (30 and 7 DTI-Days), UPGRADE (30 DTI-Days cooling-off) — also need a bundle
   before they bind (Q-035);
2. whether a recalibration trigger (SIMULATION §10: drift, regime change, sensor class change,
   audit divergence, dependency update) suspends a bundle before its window ends (Q-034;
   lab module `calibration_expiry`, readings `valid_until_expiry` / `trigger_suspends`).
