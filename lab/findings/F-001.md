# F-001 — A synchronous change of physical state triggered no re-evaluation (lab error, fixed)

**Classification:** IMPLEMENTATION_BUG (semantic verification 2026-10-07).  The "gap" reported at
checkpoint 2 came from the lab's hypothesis H-FC-5, which contradicted the texts.  Open question
Q-006 withdrawn.  Fixed in module `failure_chain` 1.2.0.
**Found by:** module `failure_chain` (S-LAB-02).  **Regression:** `tests/lab/test_findings.py`,
`tests/lab/test_failure_chain_module.py::test_value_drop_triggers_reevaluation`.

## What the lab did

Three oracle classes read every hour; the true value falls from 100 to 80 at step 6; enforcement
applies above 90.  With H-FC-5 as it stood ("only declared events — downgrades, disputes,
consistency loss — trigger re-evaluation"), the restriction and the penalty accrual continued for
18 steps on evaluation EV-001 (value 100) while every admissible class reported 80, and no
provision was reported as violated.  The lab recorded this as a protocol gap.

## Verification against the pinned text

| Place | Literal text |
|---|---|
| EB §7.1 Trigger Conditions | "new admissible data" (first of four triggers; no submission is required) |
| EB §7.2 System Behavior | "Create a new evaluation event" / "Recompute deterministically with updated inputs" |
| ETRANS §4.2 | "No enforcement output SHALL remain active solely based on past VALID state if:" … "new admissible data is introduced" |
| JUSTICE §11 | "Justice outputs SHALL be re-evaluated when: - impact metrics change," |

A fresh admissible reading that changes the state is new admissible data.  EB §7.1/§7.2 make it a
trigger for a new evaluation; ETRANS §4.2 forbids keeping enforcement on the past VALID state; JUSTICE
§11 requires re-evaluation when impact metrics change.  The chain is complete in the texts.  The lab's
H-FC-5 left out the first trigger.

## Fix (module 1.2.0)

- Input `reevaluation_policy` (source `text`): default `new_admissible_data` — a new evaluation when an
  admissible reading arrives and changes S(t).  `declared_events` is the former lab reading, kept only
  to reproduce the old result; `material_change` is an alternative with a declared tolerance.
- The independent checker derives the arrival steps from the inputs and now fails ETRANS-4.2-01 when an
  enforcement output stays on a past VALID state after new admissible data.
- Module 1.3.0 (review КТ5 reconciliation) adds ETRANS-3-03 ("No historical VALID state creates persistent
  authority"), the §3 invariant read through §4.2: the former reading fails it on the same observation, so
  that variant now has 2 FAILs.  The behaviour did not change; the set of checks did.
- Module 1.4.0 (review КТ7-GPT-01) adds the clear part of ETRANS-3-04 ("Re-evaluation is required for any
  state-dependent enforcement"): no enforcement act on a state that an admissible reading has changed since its
  evaluation.  It holds under both readings of the provision (per action, per state change) and is the same
  observation, so the former reading now has 3 FAILs.

## What remains open (not a finding)

Whether a new reading that does not change the value is "new admissible data" makes no difference to
the result (the recomputation gives the same evaluation).  The size of a "material" change matters only
for the alternative `material_change`, which the texts do not require.
