## Analysis

| | Rule A (Code A.2) | Rule B (ORACLE §3, §4.2) |
|---|---|---|
| Subject | the four-layer stack that feeds Code smart contracts | the Physical Truth Layer |
| Object | the weight of human validators | admissible sources |
| Scope | all data Code smart contracts depend on | data ingestion, weighting, aggregation, B(t) indices |
| Conditions | none | none |
| Modality | permission up to 10 % | exclusion from the protocol's scope; an oracle source is hardware |

- **Joint compliance** is possible in two ways:
  - Level 2 has weight 0: "≤ 10%" allows it, and ORACLE receives no human input.
  - Level 2 lies outside ORACLE's scope: ORACLE "excludes" what it governs, it does not forbid other
    layers.
- **Priority.** ORACLE calls itself an "integral extension" of A.2, without a priority rule.
- **Result.** The answer depends on the reading.  The Code calls B(t) "measured by Physical Truth
  Layer", and its Physical Truth Layer has four levels, one of them human.  ORACLE's Physical Truth
  Layer has hardware sources only.  Whether human validators may move B(t), and with it the B_min
  threshold of A.1, is not said.
